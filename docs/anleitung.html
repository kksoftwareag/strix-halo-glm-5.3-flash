Anleitung

Installation, Modell-Download, Build der Engines, Start des Servers – und was vor dem ersten Start zu prüfen ist.

Voraussetzungen

  • AMD Strix Halo (gfx1151) mit 128 GB, Linux mit ROCm/HIP 7.x (hipcc, /usr/lib64/rocm/llvm/bin/clang++), cmake, ninja, git.
  • Kernel-Parameter amd_iommu=off amdgpu.gttsize=126976 ttm.pages_limit=32505856.
  • Python 3.12+ (nur Standardbibliothek), uv für die Tests, die Hugging-Face-CLI hf, rund 300 GB freier NVMe-Platz.
  • Empfohlen: BIOS „UMA Frame Buffer Size“ auf 512 MiB–1 GiB (siehe Speicher).

Installation

# 1. Projekt
git clone https://github.com/kksoftwareag/strix-halo-glm-5.3-flash glm53-flash && cd glm53-flash

# 2. Modelle (speicherschonend in einer cgroup; ~95 GB je Quant)
models/fetch.sh iq2xxs        # UD-IQ2_XXS + Shard_Rewrite-Header
models/fetch.sh standard      # zusätzlich UD-Q2_K_XL und die Vision-Projektoren
./run.sh variants --create    # Shard-Sätze je Namensschema (glm5next / glm5-next)

# 3. Engines (vier HIP-Builds, je ~6 Minuten mit -j4; laufen gedrosselt)
engine/fetch.sh               # llama.cpp + Branches an den festgehaltenen Commits, Patches
engine/build.sh all hip       # oder: nohup engine/build-all.sh &

# 4. Prüfen und starten
./run.sh models               # was gefunden wurde
./run.sh show --preset unsloth-agent   # Speicherbilanz und Kommandozeile
./serve.sh --preset unsloth-agent      # Server unter dem Speicher-Wächter

Empfohlene Kommandozeile (ohne Programm)

engine/build-unsloth-hip/bin/llama-server \
  -m models/variants/UD-IQ2_XXS.glm5next/GLM-5.3-Flash-UD-IQ2_XXS-00001-of-00004.gguf \
  -ngl 99 -c 131072 -np 1 -fa on -ctk q8_0 -ctv q8_0 -b 4096 -ub 1024 -t 8 \
  --load-mode none --cache-ram 512 \
  --spec-type draft-mtp --spec-draft-n-max 2 --spec-draft-p-min 0.75 \
  --jinja --chat-template-kwargs '{"reasoning_effort": "high"}' \
  --temp 1.0 --top-p 0.95 --top-k 0 --min-p 0 \
  --host 0.0.0.0 --port 8080 -a glm-5.3-flash --metrics

Für die timkhronos-Engines (tk, ohne MTP) denselben Aufruf mit engine/build-tk-hip/bin/llama-server und dem Shard-Satz models/variants/UD-IQ2_XXS.glm5-next/, dort ohne die MTP-Zeile. Mehrere Nutzer: -np N --kv-unified. Vision: --mmproj mit dem unsloth-Projektor (glm5next) bzw. dem AesSedai-Projektor (glm5-next).

Vor dem ersten Start prüfen

  1. free -g: läuft ein anderer Server? Das Programm prüft nur MemAvailable, nicht den Nachbarn.
  2. ./run.sh show --preset …: Bewertung „passt“ oder „knapp“; bei „zu groß“ Kontext oder Quant ändern.
  3. Erster Lauf immer über bench/mem_probe.py (eine Anfrage, dann Ende): Puffergrößen und Footprint ins Speichermodell übernehmen.
  4. Dann ./serve.sh. Der Server ist unter http://<host>:8080/v1 erreichbar (OpenAI-kompatibel).

Werkzeuge

  • ./run.sh gguf-info DATEI [--stats]: Architektur, Schlüssel, Chat-Template-Optionen, Größen nach Kategorie.
  • ./run.sh rename-shard1 SRC DST --arch glm5-next: Shard-1-Header umschreiben (für Quants ohne Shard_Rewrite).
  • tools/guarded.sh -- CMD: Kommando in einer cgroup mit Speicherdeckel und Pause bei knappem RAM.
  • uv run --group dev pytest -q: Tests (GGUF-Umschreiber, Speichermodell, Presets).
